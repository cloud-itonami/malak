3. 暗号化と vault3. Encryption & vault

  • 顔特徴量 (template) は AES-256-GCM (ciphertext + wrapped key + kid) で保管。master key は JP 国内拘束。
  • 復号は murakumo on-prem の Trusted Compute エンクレーブ内でのみ。Worker / Hyperdrive / R2 経路には平文が物理的に存在しない設計。
  • 営業 lead の担当者氏名も同方式で暗号化保管。送信時のみ pod 内で展開 → message body に埋め込み → 送信後即 GC。
  • Face templates are stored as AES-256-GCM (ciphertext + wrapped key + kid). The master key is geofenced to Japan.
  • Decryption only inside the murakumo on-prem Trusted Compute enclave. Plaintext physically cannot exist on the Worker / Hyperdrive / R2 path.
  • Outreach addressee names are encrypted with the same scheme. They are decrypted inside the pod only at send time, inlined into the message body, then GC'd immediately.
